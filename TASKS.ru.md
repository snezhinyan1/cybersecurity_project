# Сборник практических задач по кибербезопасности

Сборник содержит 25 задач с решениями на Python. В каждом разделе указаны условие, пример проверки и учебные ограничения. Входные данные передаются в функции, а при запуске файла выполняется готовая демонстрация. Чтобы исследовать другой случай, измените данные в блоке `if __name__ == "__main__":`.

Для первых занятий подходят задачи 3, 11 и 16–25. Задачи 2, 7, 9 и 10 требуют знакомства с арифметикой по модулю и могут использоваться как дополнительный материал.

## 1. Проверка подмены зашифрованного сообщения

Напишите функции, которые преобразуют текст в UTF-8, выполняют XOR с повторяющимся ключом и вычисляют HMAC-SHA256 от результата. При расшифровании сначала проверьте HMAC. Измените один байт шифротекста и убедитесь, что проверка отклоняет сообщение.

Проверьте возврат исходного текста для `Привет!`, пустой строки и эмодзи. Повторяющийся XOR-ключ уязвим, пример показывает порядок шифрования и проверки целостности. [Решение](tasks/authenticated_encryption.py)

## 2. Сложение точек эллиптической кривой

Реализуйте сложение и удвоение точек кривой `y² = x³ + 2x + 2` по модулю 17. Обозначьте точку на бесконечности значением `None` и обработайте сложение противоположных точек.

Удвоение `(5, 1)` должно дать `(6, 3)`, а сумма `(5, 1)` и `(5, 16)` — `None`. Это задача об операции с точками, полноценное шифрование потребует дополнительных алгоритмов. [Решение](tasks/elliptic-curve_cryptography.py)

## 3. Исправление одиночной ошибки

Закодируйте четыре информационных бита кодом Хэмминга (7,4). Измените один из семи битов, вычислите синдром ошибки и восстановите исходные данные.

Для `[1, 0, 1, 1]` получите тот же набор после исправления ошибки в любой одной позиции. Исправление рассчитано на одну ошибку в блоке. При двух ошибках возможно неверное восстановление. [Решение](tasks/hamming_74.py)

## 4. Поиск участков с высокой энтропией

Вычислите энтропию Шеннона для каждого окна байтов и найдите окна, где она превышает 95% от оценки максимума `log₂(min(размер окна, 256))`. Проверьте, как размер окна влияет на результат.

Восемь одинаковых байтов имеют энтропию 0, а восемь разных — 3. Высокая энтропия встречается и в обычных данных, поэтому сама по себе не доказывает наличие вредоносного кода. [Решение](tasks/heuristic_analysis.py)

## 5. Проверка элемента дерева Меркла

Постройте дерево из хэшей четырёх строк `TX1`, `TX2`, `TX3`, `TX4`. По соседним хэшам и их расположению проверьте, что третья строка относится к дереву с известным корнем.

Исходное доказательство должно дать `True`. При замене хэша третьей строки или одного соседа результат должен стать `False`. Корень для сравнения должен быть получен из доверенного источника. [Решение](tasks/merkle_tree.py)

## 6. Последовательное снятие слоёв

Добавьте к сообщению три слоя XOR-преобразования с разными ключами в обратном порядке. Затем снимите их в прямом порядке, выводя начало промежуточных данных.

После снятия всех слоёв должно восстановиться сообщение `Привет`. Скрипт показывает порядок обработки слоёв. Настоящая сетевая маршрутизация и защита анонимности требуют дополнительных механизмов. [Решение](tasks/onion_routing.py)

## 7. Уравнения с небольшой ошибкой

Создайте матрицу коэффициентов `A`, секретный вектор `s` и ошибки из набора `−1, 0, 1`. Вычислите `b = A·s + e` по модулю 17. Для демонстрации используйте два уравнения с двумя неизвестными.

Проверьте каждую строку вручную. Разность между `b` и `A·s` по модулю 17 должна быть 16, 0 или 1. Маленький пример иллюстрирует задачу LWE и допускает перебор секрета. [Решение](tasks/post-quantum_cryptography.py)

## 8. Поиск хэша с заданным началом

Перебирайте целые числа `nonce` от нуля и вычисляйте SHA-256 строки `сообщение:nonce`, пока шестнадцатеричная запись хэша не начнётся с заданного числа нулей.

Для сложности 0 подходит `nonce = 0`. Для сложности 3 первые три символа результата должны быть `000`. Для опытов используйте сложность 0–3. Если за установленное число попыток подходящий хэш не найден, функция сообщает об этом. [Решение](tasks/proof_of_work.py)

## 9. Восстановление секрета по долям

Используйте интерполяцию Лагранжа по простому модулю, чтобы вычислить значение многочлена при `x = 0` по его точкам. Проверьте, что координаты `x` ненулевые и различаются по модулю.

Доли `(1, 49)`, `(2, 64)`, `(3, 87)` многочлена `42 + 3x + 4x²` при модуле 257 должны восстановить секрет 42. Для многочлена второй степени нужны три доли. Сама функция восстановления не определяет, достаточно ли предоставленных долей. [Решение](tasks/shamirs_secret_sharing.py)

## 10. Проверка знания секрета

Проследите четыре шага учебного протокола Шнорра — обязательство, вызов, ответ и проверку равенства. Используйте `p = 23`, `g = 2` и период степеней 11.

При правильном вычислении ответа обе стороны проверяемого равенства совпадают. Объясните, какие значения известны проверяющему. Параметры примера достаточно малы для перебора секрета. [Решение](tasks/zero-knowledge_proof.py)

## 11. Скрытие сообщения в младших битах

Сохраните каждый бит сообщения в младшем бите отдельного байта контейнера. Для текста используйте UTF-8. Отмечайте конец нулевым байтом, а нулевой байт внутри текста заменяйте на `FF`, который не встречается в UTF-8.

Извлечение должно возвращать `Hidden`, кириллицу и строку с нулевым символом. На каждый байт текста и один байт конца нужно восемь байтов контейнера. Скрипт работает с массивом байтов, работу с форматами изображений нужно реализовывать отдельно. [Решение](tasks/steganography_lsb.py)

## 12. Одноразовый код по времени

По секретному ключу и номеру 30-секундного интервала вычислите шестизначный TOTP-код. Используйте HMAC-SHA1, динамическое усечение и дополнение результата ведущими нулями.

Для ключа `b"12345678901234567890"` и времени 59 секунд от начала Unix-эпохи ожидается код `287082`. Генерация кода — часть системы двухфакторной аутентификации, для входа также нужны проверка и защита от повторного использования. [Решение](tasks/totp_2fa.py)

## 13. Общий секрет двух участников

Смоделируйте обмен Диффи-Хеллмана при `p = 23`, `g = 2`. Каждый участник выбирает закрытое число от 1 до 10, вычисляет открытое значение и использует полученное значение второго участника для вычисления секрета.

Секреты Алисы и Боба должны совпадать для всех допустимых пар закрытых чисел. Маленькие параметры позволяют проверить степени вручную. Для защиты от подмены участников необходима проверка их личности. [Решение](tasks/diffie_hellman.py)

## 14. Проверка пароля по сохранённому хэшу

Создайте случайную соль длиной 16 байт и получите производный ключ с помощью PBKDF2-HMAC-SHA256. При повторном вводе используйте ту же соль и то же число итераций, затем сравните результаты.

Правильный пароль должен давать `True`, другой — `False`. При повторном сохранении одного пароля случайная соль должна меняться. В примере используется 100000 итераций, чтобы показать механизм вычисления. [Решение](tasks/pbkdf2_hashing.py)

## 15. Сцепление блоков через XOR

Разбейте байты текста на блоки длиной с ключ. Добавьте маркер конца `80` в шестнадцатеричной записи и заполните оставшуюся часть последнего блока нулями. Каждый блок последовательно объедините XOR с предыдущим шифроблоком и ключом.

Ключ и IV должны иметь одинаковую ненулевую длину. Для трёх одинаковых исходных блоков первый и третий выходные блоки совпадают. Объясните это свойство учебной замены блочного шифра операцией XOR. [Решение](tasks/cbc_mode_xor.py)

## 16. Проверка учебных правил пароля

Проверьте длину пароля, наличие строчной и прописной латинских букв, цифры и символа из `!@#$%^&*`. Верните список нарушенных правил. Минимальная длина по умолчанию равна 12.

Для `SchoolPass1!` список должен быть пустым, для `abc` — содержать замечания. Выполнение этих правил само по себе не измеряет стойкость пароля к угадыванию. [Решение](tasks/password_policy.py)

## 17. Создание случайного пароля

Сгенерируйте пароль заданной длины с помощью модуля `secrets`. Используйте латинские буквы двух регистров, цифры и символы `!@#$%^&*`, обеспечив наличие каждой группы.

Проверьте длины 4 и 16. Длина меньше 4 должна отклоняться. Четыре символа используются для проверки границы алгоритма, для демонстрации выбран пароль длиной 16. [Решение](tasks/password_generator.py)

## 18. Проверка целостности документа

Прочитайте файл порциями и вычислите его SHA-256. Сохраните исходный хэш, измените содержимое и сравните новый хэш с исходным.

Для файла из байтов `abc` ожидается `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`. После изменения текста хэш должен отличаться. Для обнаружения подмены исходный хэш хранится отдельно в доверенном месте. [Решение](tasks/file_integrity.py)

## 19. Проверка документа с общим секретным ключом

Вычислите HMAC-SHA256 от байтов документа и секретного ключа. Напишите проверку метки через `hmac.compare_digest`. Сравните результаты для исходного документа, изменённого документа и другого ключа.

Только правильная комбинация документа, ключа и метки должна пройти проверку. HMAC предполагает общий секретный ключ у участников. [Решение](tasks/hmac_authentication.py)

## 20. Разграничение прав доступа

Создайте таблицу прав для ролей `viewer`, `editor`, `admin`. Разрешите просмотр всем трём ролям, редактирование редактору и администратору, удаление только администратору.

Пары `viewer/read` и `editor/edit` должны давать `True`, а `viewer/delete` и неизвестная роль — `False`. Функция иллюстрирует проверку разрешений после определения роли пользователя. [Решение](tasks/access_control.py)

## 21. Шифр Цезаря

Сдвиньте каждую латинскую букву на заданное число позиций по циклическому алфавиту. Сохраните регистр и остальные символы. Для обратного преобразования используйте отрицательный сдвиг.

Строка `Abc Xyz!` при сдвиге 3 превращается в `Def Abc!`. Сдвиг на 26 возвращает исходные буквы. Шифр легко раскрывается перебором 26 вариантов. [Решение](tasks/caesar_cipher.py)

## 22. Проверка пути к файлу

Получите относительный путь от пользователя и вычислите абсолютный путь внутри выделенной папки. Проверьте расположение после раскрытия `..` и символических ссылок. Отклоните путь, который выходит за границы папки.

Путь `report.txt` должен приниматься, а `../outside.txt` — отклоняться. Проверка отражает состояние файловой системы в момент вызова. [Решение](tasks/secure_file_paths.py)

## 23. Временная блокировка попыток входа

Храните число неудачных попыток для каждого пользователя. После третьей ошибки блокируйте новые попытки на 60 секунд. По окончании блокировки или после успешного входа сбрасывайте счётчик.

Если третья ошибка произошла в момент 10, вход должен быть заблокирован в момент 69 и доступен в момент 70. Разные пользователи имеют отдельные счётчики. Пример моделирует последовательные события в памяти одной программы. [Решение](tasks/login_rate_limit.py)

## 24. Параметризованный запрос к базе данных

Создайте в памяти SQLite таблицу пользователей и функцию поиска по имени. Передайте имя параметром SQL-запроса через `?`.

Обычное существующее имя должно находиться. Строка `alice' OR 1=1 --` должна обрабатываться целиком как имя. Если такого пользователя нет, функция возвращает `None`. Также проверьте сохранённое имя с апострофом. [Решение](tasks/parameterized_queries.py)

## 25. Маскировка адреса электронной почты

Для простого ASCII-адреса вида `имя@домен` оставьте первый символ имени, добавьте три звёздочки и сохраните домен. Имя из одного символа замените тремя звёздочками. Проверьте наличие одного `@` и точки в домене.

`student@example.com` должен превратиться в `s***@example.com`, а `a@example.com` — в `***@example.com`. Такая маскировка уменьшает объём открытых данных в журнале, но по сохранённым сведениям иногда можно узнать человека. [Решение](tasks/data_masking.py)
